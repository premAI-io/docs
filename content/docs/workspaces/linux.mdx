A Linux host can keep your workspace running when your laptop is closed. You can connect from the Mac app or use the API directly. You do not need to install a daemon on the Mac.

## 1. Check the host

Use a 64-bit glibc Linux system with systemd: Ubuntu 24.04, Debian 13, or newer. The packages support x64 and ARM64. Allow at least 8 GiB of host memory and 8 GiB of free disk space, plus files and backups.

The host needs **KVM**, Linux's hardware virtualization facility. A virtual machine also needs nested virtualization from its host provider.

Run these commands on the Linux machine:

```bash
uname -m
cat /etc/os-release
test -r /dev/kvm && test -w /dev/kvm && echo 'KVM access is ready'
```

If the last command does not print `KVM access is ready`, stop here. Ask your administrator to enable KVM and grant your user read/write access. After a group-permission change, sign out and sign in again.

<Note>
  A Raspberry Pi needs a 64-bit operating system and kernel with usable KVM. An ARM64 processor alone is not enough. Send the checks above to support if you are unsure about your Pi.
</Note>

On Ubuntu or Debian, install the native library and download tools:

```bash
sudo apt-get update
sudo apt-get install libcap-ng0 curl ca-certificates
```

## 2. Get and check the package

[Email support@premai.io](mailto:support@premai.io?subject=Fluso%20daemon%20for%20Linux) for the download links and release version. Include the OS, architecture, KVM check, and whether your desktop app is Fluso or Fluso Dev.

| `uname -m` result | Package | Checksum |
| --- | --- | --- |
| `aarch64` | `daemon-linux-arm64.tar.gz` | `daemon-linux-arm64.sha256` |
| `x86_64` | `daemon-linux-x64.tar.gz` | `daemon-linux-x64.sha256` |

Use only links supplied by Fluso. No GitHub login, Docker, or compiler is needed.

The commands below use **ARM64**, including a suitable Pi. On x64, replace `arm64` with `x64`. Replace the two URL placeholders with your links:

```bash
mkdir -p "$HOME/Downloads/fluso-daemon"
cd "$HOME/Downloads/fluso-daemon"
curl --fail --location 'ARCHIVE_URL' -o daemon-linux-arm64.tar.gz
curl --fail --location 'CHECKSUM_URL' -o daemon-linux-arm64.sha256
sha256sum -c daemon-linux-arm64.sha256
```

Continue only if the check prints `OK`. Replace `RELEASE_VERSION` with the supplied version, then extract into a new, permanent folder:

```bash
mkdir -p "$HOME/fluso/releases"
mkdir "$HOME/fluso/releases/RELEASE_VERSION" &&
  tar -xzf daemon-linux-arm64.tar.gz -C "$HOME/fluso/releases/RELEASE_VERSION"
cd "$HOME/fluso/releases/RELEASE_VERSION"
```

Keep all extracted files together. Do not overwrite an installed package. Use [update](/workspaces/manage#update-the-daemon) for later releases.

## 3. Start and configure

Run as the user who will own the workspace, without `sudo`:

```bash
./fluso-daemon setup --root "$HOME/fluso/state" --manage-host
./fluso-daemon configure --root "$HOME/fluso/state" --apply
./fluso-daemon status
```

Follow the prompts for your own model provider and key. Setup keeps data and keys under `~/fluso/state`, outside the package. It remembers this installation for later commands.

Wait for the workspace to become ready. Setup also arranges for the user service to run after logout and at boot. If administrator approval is needed, it prints a `sudo loginctl enable-linger` command. Have your administrator run that exact command.

## 4. Connect from your Mac

On the Linux host, create a fresh pairing code from the package folder:

```bash
./fluso-daemon pair --manage-host
```

Keep the code private. Each code works once and expires after ten minutes. This code gives the client workspace access and permission to change host settings.

On your Mac, open Terminal. Replace `USER` and `HOST` with your Linux login and address:

```bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:4111:127.0.0.1:4111 USER@HOST
```

Leave this terminal open. Use the same local and remote port shown by setup. The daemon checks the port in incoming requests.

1. Open **Workspaces** in the current Fluso desktop app.
2. Under **Connect a remote workspace**, enter a name, such as `Home Pi`.
3. Enter `http://127.0.0.1:4111` as the **Workspace URL**, then paste the pairing code.
4. Select **Connect**. Send a short message to check the workspace.

Closing the tunnel disconnects the client. It does not stop work on the host. Reopen the tunnel to reconnect. Pairing remains valid unless revoked or unused for 30 days.

<Accordion title="Port 4111 is already in use on my Mac">
  A Mac daemon or another tunnel may already use that port. For a new Linux installation, choose two free ports during setup, for example `--port 4211 --control-port 4212`.

  Forward `127.0.0.1:4211` to `127.0.0.1:4211` and use port `4211` in the workspace URL. For an existing host, stop its service before repeating setup with changed ports. Keep its original `--root`.
</Accordion>

<Accordion title="Use a permanent HTTPS address instead">
  For a host with DNS and a trusted TLS certificate, add `--public-origin https://workspace.example.com` during setup. Put an HTTPS reverse proxy in front of port `4111`.

  The proxy must preserve the requested Host, support streamed responses, and block `/control/*`. Keep both daemon ports on loopback. Port `4112` is private runtime control. Configure OAuth callbacks for the final HTTPS origin.

  Use the HTTPS URL and a fresh pairing code in Fluso. Ordinary remote HTTP is not accepted. Ask support for help if you do not manage this infrastructure.
</Accordion>
