Use the API to send a message, attach a document, or run a saved Agent. Your integration uses the same workspace as the Fluso app.

Start with one conversation. Add schedules, connections, or live updates when your application needs them.

</Card>

## Choose your workspace

Cloud and Fluso Local share the conversation, Agent, file, and schedule APIs. Their credentials and administration differ. Data stays in the workspace you address.

| | Cloud API | Daemon API |
| --- | --- | --- |
| Where work runs | Your Fluso Cloud workspace | Your own machine's Fluso Local workspace |
| Access for scripts | [Developer token](/api/cloud/tokens) | [Paired device token](/api/daemon/pairing) |
| Example base URL | `https://api.fluso.ai/v1` | `http://127.0.0.1:4111/v1` |
| Connected apps | Managed apps and custom MCP servers | Custom MCP servers |
| Public sharing | Agents, conversations, and files | Unavailable |
| Machine settings | Managed by the service | [Provider, sandbox, and devices](/api/daemon/settings) |

Fluso Dev uses `https://api.dev.khichdi.cc/v1`. Use credentials from the same environment as the URL.

For a remote daemon, use its HTTPS address or an [SSH tunnel](/workspaces/setup#connect-from-another-mac). A Cloud token cannot access a daemon.

## Find the exact fields

Open **Settings → Developer tokens → API reference** in Cloud. On a daemon's host, open `http://127.0.0.1:4111/docs`.

Each workspace serves its full endpoint reference at `/docs` and its OpenAPI schema at `/v1/openapi.json`. These describe the fields and operations available in that deployment. The reference also supplies runnable examples under `/v1/examples/`. The daemon serves its schema and examples locally. Its interactive reference needs internet access to load the viewer.
