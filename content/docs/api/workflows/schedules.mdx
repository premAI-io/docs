A schedule sends a message to an Agent's conversation. The app calls these schedules **routines**.

## Create a schedule

Send `POST /v1/agents/{agent_id}/schedules` with a new UUID as `id`. Keep that ID when retrying creation.

For a weekday morning brief:

```json
{
  "id": "REPLACE_WITH_NEW_UUID",
  "thread_id": "AGENT_THREAD_ID",
  "message": "Prepare a short morning brief. Start with what needs my attention today.",
  "cron": "0 9 * * 1-5",
  "timezone": "Europe/Zurich"
}
```

The conversation must belong to that Agent. Supply exactly one of `cron` or `at`. For a one-time run, use a future `at` timestamp with a UTC offset instead of `cron`.

Use an IANA timezone. At daylight-saving changes, skipped local times move forward by the gap. Repeated times run at their first occurrence.

## Review and change future work

| Action | Endpoint |
| --- | --- |
| List all schedules | `GET /v1/schedules` |
| List one Agent's schedules | `GET /v1/agents/{agent_id}/schedules` |
| Edit or pause | `PATCH /v1/schedules/{schedule_id}` |
| Delete | `DELETE /v1/schedules/{schedule_id}` |

List responses include last-run information. Follow numbered `pagination.page` and `pages`. Use `attention=true` on `/v1/schedules` to find schedules needing review. Pause with `{"status":"paused"}` or resume with `{"status":"active"}` through PATCH. Read the schedule again to confirm its saved state.

Keep the schedule ID and unchanged settings when retrying creation. A new ID creates another schedule. To change between recurring and one-time timing, supply exactly one of `cron` or `at`.

Deleting a schedule prevents future submissions. It does not cancel already accepted work. [Cancel that run separately](/api/workflows/runs#stop-work) if needed.

On a daemon, the host must be awake for work to run. After downtime, missed recurring runs are combined into one catch-up run. Failed scheduled work can pause the schedule for attention.
