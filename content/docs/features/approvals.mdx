Fluso uses two approval modes for connected-app and MCP tools: **Ask me first** and **Allow everything**. Saved tool rules and network-access restrictions also apply.

## Choose an approval mode

| Mode | Behavior |
|---|---|
| **Ask me first** | Ask for tools that do not already have an effective Allow rule |
| **Allow everything** | Approve tools automatically, including Ask rules; Deny rules still block |

Read-only tools follow each connection's settings. **Ask me first** does not force an approval for a tool that already has permission to run.

Use the hand or open-lock control beside the reasoning mode in the composer. `⌘⇧\` switches between the two modes.

- In an existing chat, changing the control sets an override for that chat.
- On a new-chat screen, it changes your saved account default immediately.
- Chats without their own override follow the account default, including existing chats.
- Chats with an override keep it when you change the default.

## Manage the account default

Open your account menu, choose **Settings**, then **Approvals & permissions**. **Auto-approval** changes your account default for chats without an override. Changing one chat does not rewrite every other chat's override.

## Approval cards

When a connected-app tool needs approval, the card shows the app or server, tool name, a short argument summary, and the exact arguments.

- **Allow once** permits the displayed request once.
- **Always allow** saves an allow rule for that tool.
- **Deny** rejects the request without creating a permanent tool deny.

If an app is missing, use **Connect** and complete sign-in. If the request changes, expires, or is canceled while you are deciding, the old card cannot approve a new action. Ask Fluso to retry it.

<Note>
  Use **Ask me first** and set external write tools to **Ask** when you want to review each message, invitation, or change before it is sent. **Allow everything** bypasses Ask prompts, including explicit Ask rules.
</Note>

## Saved tool rules

Open **Plugins → MCP**, expand a connection, and review **Tool permissions**.

- **Allow** permits the tool without asking, unless a higher-priority policy blocks it.
- **Ask** requires approval in **Ask me first** mode. **Allow everything** automatically approves it.
- **Deny** blocks it.
- **Auto-approve read-only tools** permits tools classified as read-only. Explicit Ask and Deny rules take precedence over read-only auto-approval, but **Allow everything** still bypasses Ask.

Network policy can block a connection independently of its tool permissions. Installing a skill or enabling **Allow everything** does not remove network restrictions or tool Deny rules.

## Troubleshooting

<AccordionGroup>
  <Accordion title="I changed Settings, but this chat behaves differently">
    Check the control in this chat. A chat-specific override takes precedence over the account default.
  </Accordion>
  <Accordion title="A tool set to Ask runs without prompting">
    Check the current chat mode. **Allow everything** approves Ask rules automatically. Switch to **Ask me first** to require the prompt.
  </Accordion>
  <Accordion title="A tool runs in Ask me first without prompting">
    Check for an existing Allow rule or enabled read-only auto-approval. The chat mode is the fallback for tools without an applicable saved rule.
  </Accordion>
  <Accordion title="A tool is blocked without a card">
    Check for a Deny rule. For a separate network-policy block, contact the deployment operator.
  </Accordion>
</AccordionGroup>
