Connections give Fluso access to external tools through MCP. You can connect an app from the catalog or add your own MCP server.

## Connect an app

1. Open **Plugins → MCP**.
2. Select **Add MCP**, then **Apps**.
3. Search for the app you need and select **Connect**.
4. Complete the sign-in or credential form shown for that app.
5. Check that the connection appears as connected.

Ordinary chats can use the connection on their next message. For a saved Agent, also select it under [Connectors](/developers/guides/settings#grant-app-access).

You can also request a connection in chat. Use the **Authorize** card when it appears, then check the result before continuing.

## Native Fluso connectors

The Fluso mark beside an app identifies a **Native** connector built and run by Fluso. These connectors use Fluso's own connection flow instead of Composio.

The catalog can also contain provider-managed connections and vendor-hosted MCP services. Check the app and sign-in screen you are using. A native connector still calls the connected service, such as Google or Slack. It does not move that service's processing into Fluso or into an enclave.

Use the current catalog as the list of available connections. A connector's presence in source code or an earlier screenshot does not mean it is enabled for your account.

### Google services connect separately

**Gmail**, **Google Calendar**, **Google Drive**, **Google Docs**, **Google Sheets**, and **Google Slides** have separate entries. Connect the services you need and check each one's status. Connecting Gmail alone does not connect Calendar or Drive.

Google may reuse an existing consent for related services. Review the permissions it requests rather than assuming that one sign-in grants the whole suite.

### OAuth and API keys

Many apps open their own sign-in page. Some require an API key, personal token, or account name. Follow the selected app's form. Your provider account and its permissions still determine what Fluso can access.

If an older connection asks you to reconnect after the native connector rollout, open the current catalog entry and finish that flow. Check the connection and any saved Agent selections before running unattended work.

## Connect a custom server

In **Add MCP**, choose **Custom server** and enter the server's Streamable HTTP endpoint.

The endpoint must be reachable from Fluso over public HTTPS. A `localhost` address, private-network address, or `stdio` command is not a supported Cloud connection URL. Network and provider policies also apply.

Select **Continue** to discover the server's authentication options:

| Method | What to provide |
| --- | --- |
| **OAuth** | Sign in through the server's authorization flow |
| **OAuth (BYO)** | Your registered client ID and any required client secret or OAuth endpoints |
| **API key** | The key and header name expected by the server; the default is `X-Api-Key` |
| **Bearer** | The token expected in the `Authorization` header |

For a custom OAuth client, the callback is `https://api.fluso.ai/v1/mcp-oauth/callback`.

Only connect servers you trust. Review requested access before authorizing them. A successful sign-in does not establish that every tool works or is permitted.

## Tool permissions

Expand a connection to inspect its tools and set **Allow**, **Ask**, or **Deny**:

- **Allow** lets that tool run without a per-call approval.
- **Ask** requests approval when the chat uses **Ask me first**.
- **Deny** blocks the tool, including in **Allow everything** mode.

**Auto-approve read-only tools** permits tools classified as reads unless an explicit Ask or Deny rule applies. **Allow everything** can bypass Ask, but cannot bypass Deny or organization restrictions.

For email or other external messages, request a draft, use **Ask me first**, and keep send tools on **Ask**. See [Approvals and permissions](/features/approvals).

## Reconnect or disconnect

Use the connection row's menu to reconnect when access expires, or disconnect when you no longer want Fluso to use it. Actions depend on the connector; a shared built-in service may not offer a personal reconnect control.

Disconnecting removes Fluso's saved connection. You can also revoke access in the provider's settings. Disconnecting does not delete content already saved in conversations or files, or undo actions already completed.

For Google services, check each related service after disconnecting or revoking access. Some services share an underlying grant.

## Troubleshooting

<AccordionGroup>
  <Accordion title="An app is missing from the catalog">
    Search by the service name. If it is still missing, contact [support](mailto:support@premai.io). A public HTTPS MCP endpoint can be an alternative, but a listed app elsewhere is not a guarantee of a supported Fluso connection.
  </Accordion>
  <Accordion title="Connected, but a tool fails">
    Read the error and check the provider account's permissions. Reconnect if authorization expired. A connection can be saved even when a provider tool is unavailable or rate-limited.
  </Accordion>
  <Accordion title="Google sign-in succeeded but Calendar is missing">
    Connect **Google Calendar** separately. Gmail, Calendar, and Drive have their own catalog entries.
  </Accordion>
  <Accordion title="An Agent cannot use a connection">
    Check that the connection is selected in the Agent's setup. Then check its read-only setting and saved tool rules. Account connection and Agent access are separate choices.
  </Accordion>
  <Accordion title="Custom OAuth cannot register a client">
    Check that the URL is the MCP endpoint. If the server does not support dynamic registration, use **OAuth (BYO)** with a client registered with that provider.
  </Accordion>
</AccordionGroup>
