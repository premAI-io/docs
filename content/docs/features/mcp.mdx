Connections give Fluso access to external tools through MCP. You can connect an app from the catalog or add your own MCP server.

## Connect an app

1. Open **Plugins → MCP**.
2. Select **Add MCP**, then **Apps**.
3. Search for the app you need and select **Connect**.
4. Complete the sign-in or credential form shown for that app.
5. Check that the connection appears as connected.

Ordinary chats can use the connection on their next message. For a saved Agent, also select it under [Connectors](/developers/guides/settings#grant-app-access).

You can also request a connection in chat. Use the **Authorize** card when it appears, then check the result before continuing.

## Three kinds of connection

Every connection on **Plugins → MCP** is one of three kinds. They all work the same way in chat and in Agents, with the same tool permissions.

| Kind | How to spot it | Who runs it |
| --- | --- | --- |
| **Native** | The Fluso mark after the app's name. Hover it to see "Native · built and run by Fluso". | Fluso. The connector calls the app's own API with your sign-in. |
| **Third-party** | An app in the catalog with no Fluso mark. | Composio, a connection provider, runs it for Fluso. |
| **Custom** | A server you added on the **Custom server** tab. | You, your team, or the app's vendor. |

A native connector still sends your requests to the app you connected, such as Slack or Google. It does not move that app's processing into Fluso or into an enclave.

When an app has a native connector, Fluso uses it instead of the third-party version. See [Moving to native connectors](#moving-to-native-connectors) if you connected an app before it went native.

### Native connectors

Native connectors launched in November 2026. The catalog in **Add MCP** is the current list, and it changes as apps are added. Your account may not show every app.

| Area | Apps |
| --- | --- |

| Chat and meetings | Discord, Fathom, Pushbullet, Slack, Webex |

| Files | Box, Dropbox |

The rest of the catalog is third-party apps. They connect and work as before.

### How you sign in

What the app asks for depends on the app:

- **Sign in on the app's page.** Most apps, including Google, Slack, GitHub, and Notion. Approve the access on the app's screen and the window closes.
- **Paste an API key.** Some apps, such as Stripe, Supabase, Sentry, Asana, and Cal.com, use a key or personal token instead. Create one in the app's settings, usually under API or Developer, and paste it into the form Fluso shows. Fluso checks the key before it saves the connection and stores it encrypted. The key's own permissions limit what Fluso can do, so a restricted or read-only key keeps Fluso restricted too.
- **Nothing to connect.** **Web Search** is on for every account. Its menu shows **On for everyone** and has no **Disconnect**.

Your account on the app still decides what Fluso can reach.

### Google services connect separately

**Gmail**, **Google Calendar**, **Google Drive**, **Google Docs**, **Google Sheets**, and **Google Slides** have separate entries. They replace the single **Google Workspace** connection. Connect the services you need and check each one's status. Connecting Gmail alone does not connect Calendar or Drive.

Google may reuse an existing consent for related services. Review the permissions it requests rather than assuming that one sign-in grants the whole suite.

## Moving to native connectors

When a native connector replaces an app you connected through the third-party version, the old connection stops working and leaves your list. You do not need to delete it. Connect the native version once.

<Steps>
  <Step title="Find the apps to reconnect">
    A banner at the top of the app reads **We've upgraded Fluso's app connections** and names the apps you need to reconnect. Select **Reconnect**.
  </Step>
  <Step title="Connect the native version">
    On **Plugins → MCP**, select **Add MCP**, find each app, and select **Connect**. For the old **Google Workspace** connection, connect **Gmail** and any other Google services you use.
  </Step>
  <Step title="Check tool permissions">
    Per-tool rules from the old connection do not move over, because the native connector has its own tools. Open **Tool permissions** on the new connection and set the rules you want.
  </Step>
</Steps>

The banner stops naming an app once you connect its native version. For Google, connecting Gmail clears it.

**Your Agents keep their access.** If an Agent could use the old app, it gets the same access to the native version: **Allowed** stays **Allowed** and **Read only** stays **Read only**. Access to the old Google Workspace connection covers all six Google services. You do not need to edit the Agent. Reconnect the app before the Agent's next routine, because a routine cannot use an app that is not connected.

If you select an old app that has been replaced, Fluso says it **has been upgraded** and points you to the native version.

## Connect a custom server

In **Add MCP**, choose **Custom server** and enter the server's Streamable HTTP endpoint.

The endpoint must be reachable from Fluso over public HTTPS. A `localhost` address, private-network address, or `stdio` command is not a supported Cloud connection URL. Network and provider policies also apply.

Select **Continue** to discover the server's authentication options:

| Method | What to provide |
| --- | --- |
| **OAuth** | Sign in through the server's authorization flow |
| **OAuth (BYO)** | Your registered client ID and any required client secret or OAuth endpoints |
| **API key** | The key and header name expected by the server; the default is `X-Api-Key` |
| **Bearer** | The token expected in the `Authorization` header |

For a custom OAuth client, the callback is `https://api.fluso.ai/v1/mcp-oauth/callback`.

Only connect servers you trust. Review requested access before authorizing them. A successful sign-in does not establish that every tool works or is permitted.

## Tool permissions

Open a connection's **•••** menu and select **Tool permissions** to see its tools and set **Allow**, **Ask**, or **Deny**:

- **Allow** lets that tool run without a per-call approval.
- **Ask** requests approval when the chat uses **Ask me first**.
- **Deny** blocks the tool, including in **Allow everything** mode.

**Auto-approve read-only tools** permits tools classified as reads unless an explicit Ask or Deny rule applies. **Allow everything** can bypass Ask, but cannot bypass Deny or organization restrictions.

For email or other external messages, request a draft, use **Ask me first**, and keep send tools on **Ask**. See [Approvals and permissions](/features/approvals).

## Reconnect or disconnect

Use the connection row's menu to reconnect when access expires, or disconnect when you no longer want Fluso to use it. Actions depend on the connector; a shared built-in service may not offer a personal reconnect control.

Disconnecting removes Fluso's saved connection. You can also revoke access in the provider's settings. Disconnecting does not delete content already saved in conversations or files, or undo actions already completed.

For Google services, check each related service after disconnecting or revoking access. Some services share an underlying grant.

## Troubleshooting

<AccordionGroup>
  <Accordion title="An app is missing from the catalog">
    Search by the service name. If it is still missing, contact [support](mailto:support@premai.io). A public HTTPS MCP endpoint can be an alternative, but a listed app elsewhere is not a guarantee of a supported Fluso connection.
  </Accordion>
  <Accordion title="Connected, but a tool fails">
    Read the error and check the provider account's permissions. Reconnect if authorization expired. A connection can be saved even when a provider tool is unavailable or rate-limited.
  </Accordion>
  <Accordion title="An app I connected before asks me to reconnect">
    It now has a native connector. Connect the native version from **Add MCP**. See [Moving to native connectors](#moving-to-native-connectors).
  </Accordion>
  <Accordion title="Google sign-in succeeded but Calendar is missing">
    Connect **Google Calendar** separately. Gmail, Calendar, and Drive have their own catalog entries.
  </Accordion>
  <Accordion title="An Agent cannot use a connection">
    Check that the connection is selected in the Agent's setup. Then check its read-only setting and saved tool rules. Account connection and Agent access are separate choices.
  </Accordion>
  <Accordion title="Custom OAuth cannot register a client">
    Check that the URL is the MCP endpoint. If the server does not support dynamic registration, use **OAuth (BYO)** with a client registered with that provider.
  </Accordion>
</AccordionGroup>
