Each saved Agent has one main conversation. Open the Agent in the workspace to continue it. The Agent can delegate bounded tasks into separate sessions when work needs its own conversation.

> *"Review this customer incident. Gather the impact and missing details, then prepare an internal escalation. Do not contact anyone yet."*

## Context map

| Source | Main conversation | Delegated session |
| --- | --- | --- |
| Agent instructions, capabilities, and knowledge-file selection | Current saved configuration on the next turn | Configuration captured when the session was created |
| Conversation history | Continues across turns | Its own history; a fork also starts with completed parent context |
| Project files | Conversation's project | Parent's project |
| Project working memory | Recent project summaries can be recalled | Recent project summaries can be recalled |
| Delegated task | Your request and follow-ups | The task message sent by the parent |

Editing an Agent does not change work already running. The main conversation picks up the new configuration on its next turn; an existing delegated session keeps its saved configuration.

Ordinary chats can use global preferences, project instructions, and `context.md`. Saved Agent conversations use their own instructions instead, while retaining access to project files and working-memory summaries.

## Keep contexts isolated

Each conversation keeps its messages and turn state. Project files and working memory can still be shared, so separate conversations are not separate file sandboxes.

The current Agent interface does not create several independent top-level chats for one Agent. Duplicate the Agent when you need a separate setup and main conversation. Choose a different project as well if its files and working memory should be separate.

Changing an Agent's configured project does not move an existing conversation or its files. See [Project context](/developers/project-context).

## Use parent and child threads

A main Agent conversation can create direct child sessions for bounded work. A child cannot create another child. The parent can follow up with its children and receive their results.

The Agent's session tool supports two ways to start a child:

- A fresh session receives the task message and the Agent/project context, without the parent's transcript.
- A fork also receives the parent's completed context at the fork point. It does not inherit unfinished work from the current turn.

Give each task an expected result, necessary sources, and approval boundaries. Use independent sessions for read-only research or different outputs; coordinate changes to shared files in one conversation.

Thread creation is guided by the task and Agent instructions. The current editor has no Off, Explicit, or Proactive thread-management selector.

## Pick the right scope

- Put stable Agent behavior in **Purpose and instructions**.
- Add reference material as knowledge files.
- Keep working files in the conversation's project.
- Delegate a bounded task when it needs a separate conversation.
- Duplicate an Agent for an independent main conversation.
