Saving an Agent creates a configuration snapshot. The main conversation uses the current snapshot on its next turn; existing delegated sessions keep the snapshot they started with.

Use **Modify** in the Agent menu or **Edit** in its details to change the setup. The current interface has no Version history or rollback screen. Keep a copy of instructions you may want to restore, then save those fields again if needed. API updates use `currentConfigId` to detect conflicting edits; see [Agents and versions](/developers/api-ref/agents-and-versions).

## Move an Agent between workspaces

Use **Share** in the Agent menu to publish a setup that another person can inspect and import as an independent Agent.

### Create a public link

Review the instructions and choose whether to include:

- **Custom skills**, including files in each selected skill's folder.
- **Knowledge files**, including the contents of selected files.
- **Custom connections**, including their server URLs and connection settings.

Select **Create public link**, then copy the link. Shared resources have a combined 20 MiB limit.

<Warning>
  Anyone with the link can read the published setup and included resources. Inspect files and connection URLs for sensitive data before publishing. App credentials, chat history, and routines are not included.
</Warning>

Built-in skills and resources you do not include remain references for the recipient to review. Project files are not automatically part of an Agent share; [export the project as ZIP](/features/projects#export-a-project) separately when needed.

### Update or stop sharing

Edits to your Agent do not automatically update the published snapshot. Open **Share** and choose **Update shared version** to publish the current setup.

Choose **Stop sharing** to revoke the public link. This stops future access through the link; it does not remove copies already imported or downloaded by someone else.

### Import a copy

Open the shared link and review its instructions, capabilities, and included files before importing. You can also start from **Agents → New Agent → Import from a shared link**.

Choose the new Agent's name and destination project. Connect your own Apps and review permissions before using it. The imported Agent has its own conversation and routines; future changes to the source do not update your copy.

The current interface uses share links for this flow. It does not offer the older Export YAML or Import Agent file controls.

## Duplicate in your workspace

Choose **Duplicate** in the Agent menu for a separate Agent with copied configuration and knowledge. Its conversation and routines start separately. Check the project before testing: duplicates can still work with the same project files.

## A practical handoff

Share the Agent setup, provide any additional project files separately, and ask the recipient to connect their own Apps. Review [approval settings](/features/approvals), then [test the copy](/developers/evaluations) before using it for customer work.
