The current Agents release does not expose an inbound webhook trigger interface or the earlier Agent webhook endpoints. Instructions referring to **Triggers**, webhook secrets, delivery receipts, or an Agent **Analytics** page do not apply to this release.

## Integrate an external event

A service you control can receive an event, authenticate it, and call the [Fluso chat API](/developers/api-ref/threads-and-messages#send-a-message) with your Fluso bearer token. This requires your own event handler; Fluso does not provide a webhook URL for it.

- Keep the bearer token on your server.
- Validate the event and send only the fields the Agent needs.
- Reuse the Agent's existing main conversation.
- Use a unique `requestId` for each intended turn and preserve it when retrying that turn.
- Follow the [run](/developers/api-ref/runs) to determine whether work completed.

Treat event text as untrusted input. Review [approval settings](/features/approvals) before allowing an event to cause an external write. An accepted chat request is not proof that the work finished.

## Time-based work

Use [Schedules](/developers/schedules) when a saved message should run at a future time or on a recurring routine.
