The account API lets an integration use the same conversations, Agents, and files as Fluso. Cloud and the daemon share these operations. You do not need a separate API project or a runtime ID.

## Choose your workspace

| Workspace | API base URL | Full guide and endpoint reference |
| --- | --- | --- |
| Fluso Cloud | `https://api.fluso.ai/v1` | **Settings → Developer tokens → API reference** in your app |
| Fluso Dev | `https://api.dev.khichdi.cc/v1` | [Development API reference](https://api.dev.khichdi.cc/docs) |
| Daemon, default local port | `http://127.0.0.1:4111/v1` | Open `http://127.0.0.1:4111/docs` on its host or through your tunnel |
| Daemon, HTTPS | Your workspace URL followed by `/v1` | Your workspace URL followed by `/docs` |

The reference includes request bodies, response fields, and runnable examples. Its OpenAPI schema is at `/v1/openapi.json`. A daemon lists the endpoints it supports. Cloud account administration and public sharing do not transfer to it.

<Note>
  These examples need the current account API. If **Developer tokens** is missing from your app, contact [support](mailto:support@premai.io) to confirm availability for your release.
</Note>

## Get a token

### Fluso Cloud

In **Fluso → Settings → Developer tokens**, create a token. Choose **Read only** to inspect existing data, or **Read and write** to submit work and edit it. Use **Read and write** for the quickstart below. Copy the secret when shown. It cannot be retrieved later.

A write token can also connect services and approve individual tool calls. Managing credentials and permanent tool permissions requires a signed-in app session.

### Your daemon

Configure the [daemon](/workspaces) and its model provider first. On its host, run `./fluso-daemon pair` from the installed package folder. Exchange the one-use code at the daemon's address:

```bash
curl --fail-with-body --silent --show-error \
  'http://127.0.0.1:4111/daemon/v1/pair' \
  -H 'Content-Type: application/json' \
  --data-raw '{"code":"PAIRING_CODE","name":"My integration"}'
```

Replace `PAIRING_CODE` before running. Save the returned `token` and client `id` privately. Codes expire after ten minutes. A device token grants read/write access to the owner's workspace, including tool approvals.

Use `pair --manage-host` only when the client also needs provider settings, host-file access, or permission to invite devices. Remote connections require [HTTPS or an SSH tunnel](/workspaces/linux#4-connect-from-your-mac).

## Try a complete request

Open Bash in a new example directory. You need cURL 7.87 or later, `jq`, and `uuidgen` for the API examples. Check your version with `curl --version`. The example below uses a daemon. For Cloud, use your environment's URL from the table above. Set the token you saved:

```bash
export FLUSO_API_URL='http://127.0.0.1:4111/v1'
export FLUSO_API_TOKEN='YOUR_TOKEN'
```

Keep real tokens out of source control, shared terminal recordings, and URLs. Use a secret store for deployed integrations.

Download the example from that workspace. Read it before running:

```bash
curl --fail --silent --show-error \
  "$FLUSO_API_URL/examples/quickstart.sh" -o quickstart.sh
cat quickstart.sh
```

Then run it in the same Bash shell:

```bash
source quickstart.sh
```

The script creates a conversation, requests a short answer, waits for the run, and reads every result page. It keeps `thread_id`, `run_id`, `input_key`, and `input_body` for follow-ups.

A timeout does not cancel accepted work. Do not rerun the quickstart to recover it: that creates a new request. Read the [saved run and results](/developers/api-ref/runs) instead.

## Keep access under control

Cloud developer tokens expire after 90 days by default. To rotate one, create a replacement in Settings, update your integration, verify it, then revoke the old token. Revocation can take up to 30 seconds to reach cached authentication and open streams.

Daemon device tokens expire after 30 idle days. Authenticated use renews them. Revoke a device with `DELETE /daemon/v1/clients/{clientId}`. A device can revoke itself. Host-management access also permits revoking other devices.

Native applications can use the Cloud browser sign-in flow instead of developer tokens. Follow **auth** in your app's **API reference**, including its code-verifier and refresh-token requirements. Do not reuse an old refresh token after rotation.
