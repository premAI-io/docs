Usage reports describe recorded activity. They can arrive after execution and are not a final bill. A missing report or unknown price does not mean zero cost.

## Read workspace totals

Use `GET /v1/token-usage` for account totals and its session summaries. Public response fields use snake_case, such as `last_updated` and `entry_count`.

## Inspect a run

`GET /v1/threads/{thread_id}/runs/{run_id}/usage` returns the run's recorded tokens and estimated cost. It returns `null` when no usage is reported. Cost can also be null when a recorded call has no price.

For individual records, use `GET /v1/token-usage/entries` with `thread_id` and `run_id`. Other filters include `provider`, `model`, `since`, and `limit`.

```bash
curl --fail-with-body --silent --show-error --get \
  "$FLUSO_API_URL/token-usage/entries" \
  -H "Authorization: Bearer $FLUSO_API_TOKEN" \
  --data-urlencode "thread_id=$thread_id" \
  --data-urlencode "run_id=$run_id"
```

Set the API URL, token, and IDs through the [quickstart](/developers/api-ref/authentication#try-a-complete-request) first. Read access is sufficient for usage queries. They do not start workspace compute.

Use your [workspace's endpoint reference](/developers/api-ref/authentication#choose-your-workspace) for all fields and filters. For daemon inference charges, check the model provider's billing as well.
