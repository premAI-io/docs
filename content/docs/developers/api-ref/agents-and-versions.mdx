An Agent record points at one immutable configuration through `currentConfigId`. Use that ID as `baseConfigId` when you update the Agent.

For editing, copies, and public links, see [Configuration and sharing](/developers/versions). Current configuration responses use `schemaVersion: 2`.

Agent-owned work runs in [threads](/developers/api-ref/threads-and-messages) and can start from [schedules](/developers/api-ref/schedules). Agents is a beta workspace; access also depends on the deployment configuration. See [Webhooks](/developers/webhooks) for the current event-integration boundary.

## List Agents

<Endpoint method="GET" path="/v1/agents" />

Returns paginated Agent summaries, with optional text search through `q`.

```bash title="Request"
curl "$FLUSO_API/v1/agents?page=1&limit=20&q=release" \
  -H "Authorization: Bearer $FLUSO_TOKEN"
```

## Create an Agent

<Endpoint method="POST" path="/v1/agents" />

Creates an Agent and its first immutable configuration.

Create `Release Review` through `POST /v1/agent/projects` first. `Home` is available by default.

```bash title="Request"
curl "$FLUSO_API/v1/agents" \
  -X POST \
  -H "Authorization: Bearer $FLUSO_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Release reviewer",
    "instructions": "Reviews release candidates. Return a go or no-go decision, cite blockers, and name each follow-up owner.",
    "conversationStarters": ["Review this candidate"],
    "responseMode": "high",
    "projectName": "Release Review"
  }'
```

## Read the current configuration

<Endpoint method="GET" path="/v1/agents/{agentId}" />

Returns the Agent record and the configuration named by `currentConfigId`.

```bash title="Request"
curl "$FLUSO_API/v1/agents/agt_0123456789ab4def8123456789abcdef" \
  -H "Authorization: Bearer $FLUSO_TOKEN"
```

```json title="Response: 200, selected fields"
{
  "agentId": "agt_0123456789ab4def8123456789abcdef",
  "currentConfigId": "cfg_11111111111141118111111111111111",
  "state": "active",
  "config": {
    "schemaVersion": 2,
    "configId": "cfg_11111111111141118111111111111111",
    "name": "Release reviewer",
    "instructions": "Reviews release candidates. Return a go or no-go decision, cite blockers, and name each follow-up owner."
  }
}
```

## Publish an update

<Endpoint method="PATCH" path="/v1/agents/{agentId}" />

Creates a new configuration when the submitted fields change the Agent.

```bash title="Request"
curl "$FLUSO_API/v1/agents/agt_0123456789ab4def8123456789abcdef" \
  -X PATCH \
  -H "Authorization: Bearer $FLUSO_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "baseConfigId": "cfg_11111111111141118111111111111111",
    "instructions": "Review release candidates. Return a go or no-go decision with named owners and evidence for each blocker."
  }'
```

```json title="Response: 200, selected fields"
{
  "agentId": "agt_0123456789ab4def8123456789abcdef",
  "currentConfigId": "cfg_22222222222242228222222222222222",
  "state": "active",
  "config": {
    "schemaVersion": 2,
    "configId": "cfg_22222222222242228222222222222222",
    "instructions": "Review release candidates. Return a go or no-go decision with named owners and evidence for each blocker."
  }
}
```

An unchanged patch returns the existing config ID. A stale `baseConfigId` returns `409 STALE_AGENT_CONFIG` and includes the current config ID in `error.details.currentConfigId`.

## Configuration lifetime

The current API exposes the current configuration through `GET /v1/agents/{agentId}`. There is no `/versions` listing endpoint in this release. Keep copies of editable fields in your own system if you need a revision history.

The main Agent conversation adopts the current configuration on its next turn. A turn already running keeps its accepted configuration, and existing delegated sessions retain their original configuration. Editing `projectName` does not move existing conversations or their files.

## Editable fields

Create accepts `name`, `instructions`, `conversationStarters`, `responseMode`, `projectName`, `skills`, and `connectors`, plus an optional UUID `creationId` for creation retries. Update requires `baseConfigId` and accepts the editable fields; attached `knowledgeFiles` are update-only.

- `responseMode` is `high` or `fast`.
- `skills: null` leaves skills unrestricted by the Agent; `skills: []` selects none.
- `connectors: null` leaves connections unrestricted by the Agent; `{}` selects none. Entries map MCP server IDs to `allow`, `read_only`, or `deny`.
- The Agent's selections do not grant new App access or bypass account permissions.
- Legacy `description`, `goal`, `threadManagementEnabled`, and `threadCreationMode` inputs are rejected.

## Delete an Agent

<Endpoint method="DELETE" path="/v1/agents/{agentId}" />

Deletes the Agent and its owned chats, configurations, knowledge, and schedules. This also removes its active share links.

```bash title="Request"
curl "$FLUSO_API/v1/agents/agt_0123456789ab4def8123456789abcdef" \
  -X DELETE \
  -H "Authorization: Bearer $FLUSO_TOKEN"
```

```http title="Response"
HTTP/1.1 204 No Content
```
