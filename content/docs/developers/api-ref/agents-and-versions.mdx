These are authenticated beta client routes. Agent fields use camelCase and configurations use `schemaVersion: 2`. The current model has instructions, skills, app policies, and knowledge files; it has no separate description, goal, or thread-management mode.

For the user workflow, see [Create and refine](/developers/agent-builder).

## Create and read

<Endpoint method="POST" path="/v1/agents" />

Creating a definition does not create or run a conversation. The project must already exist; `Home` is the default.

```bash
curl "$FLUSO_API/v1/agents" \
  -H "Authorization: Bearer $FLUSO_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Release reviewer",
    "instructions": "Review supplied evidence. Separate blockers from missing information. Do not publish or contact anyone.",
    "conversationStarters": ["Review this release candidate"],
    "responseMode": "high",
    "projectName": "Home",
    "skills": ["pdf", "docx"],
    "connectors": {}
  }'
```

The `201` response contains `agentId`, `currentConfigId`, and `config`. Save the returned IDs. An optional UUID `creationId` supports retrying the same creation.

| Method and path | Result |
| --- | --- |
| `GET /v1/agents?page=1&limit=50&q=release` | Agent summaries and pagination; `purpose` is derived from instructions |
| `GET /v1/agents?all=true` | The complete bounded library in one response |
| `GET /v1/agents/{agentId}` | Current Agent record and configuration |
| `GET /v1/agents/{agentId}/chats` | Main conversation, delegated sessions, and Manager, including role and earlier-setup markers |

## Update without overwriting someone else's edit

<Endpoint method="PATCH" path="/v1/agents/{agentId}" />

Read the Agent first. Send its `currentConfigId` as `baseConfigId`, with only the fields you intend to change.

```json
{
  "baseConfigId": "<currentConfigId from GET>",
  "instructions": "Review supplied evidence. Missing evidence remains unresolved. Do not publish or contact anyone."
}
```

A stale revision returns `409 STALE_AGENT_CONFIG`. Read again and reapply the intended change; do not blindly resend all fields from an old form.

Omitted fields stay unchanged. Submitted lists and connector maps replace the whole field.

| Field | Meaning |
| --- | --- |
| `skills: null` | All skills available to an ordinary chat, including later additions |
| `skills: []` | No selected skills |
| `connectors: null` or `{}` | No app grants |
| `connectors: {"<serverId>": "allow"}` | Selected connection permitted, subject to account and approval policies |
| `read_only` / `deny` | Restrict that connection to classified read-only tools, or block it |

The main conversation follows the current setup on its next accepted turn. Running turns and existing delegated sessions retain their accepted configuration. Changing `projectName` does not move existing conversations.

Configurations are stored internally, but there is no current public version-list or rollback endpoint.

## Attach knowledge

<Endpoint method="POST" path="/v1/agents/{agentId}/knowledge-files" />

Upload one multipart `file`, or use `POST /v1/agents/{agentId}/knowledge-files/from-workspace` with `{"path": "/projects/Home/files/rubric.md"}`.

The response is a knowledge reference with `fileId`, `name`, `fileName`, and `bytes`. Attaching stores a copy; it does not add that reference to the active setup. PATCH `knowledgeFiles` with the full desired list and the latest `baseConfigId` to save it. Preserve entries you still want.

Limits: 25 knowledge entries, 20 MiB per file, 4,000 instruction characters, three starters of 200 characters each, and 100 Agents per user. Workspace storage limits also apply.

## Copy, share, or delete

| Method and path | Behavior |
| --- | --- |
| `POST /v1/agents/{agentId}/duplicate` with `{}` | Independent setup and knowledge copy; no conversations or routines |
| `POST /v1/agents/{agentId}/star` with `{"starred": true}` | Set the library star |
| `DELETE /v1/agents/{agentId}` | Delete the Agent and its conversations, remove schedules, and revoke its public link |

Sharing uses [separate snapshot routes](/developers/api-ref/sharing). To do work, [open the main conversation and send a message](/developers/api-ref/threads-and-messages).
