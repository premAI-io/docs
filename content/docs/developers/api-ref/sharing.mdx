Public sharing is Cloud-only. Sharing an Agent stores a public snapshot. It does not expose a live view of the owner's workspace. Owner routes require [authentication](/developers/api-ref/authentication). A public snapshot read does not.

## Publish and revoke

| Method and path | Behavior |
| --- | --- |
| `GET /v1/agents/{agent_id}/share-options` | Available custom skills, knowledge, and custom connections |
| `GET /v1/agents/{agent_id}/share` | Current link record or `null` |
| `POST /v1/agents/{agent_id}/share` | Publish a snapshot |
| `POST /v1/agent-shares/{share_id}/refresh` | Replace the snapshot at the same link |
| `DELETE /v1/agent-shares/{share_id}` | Revoke the link |

Publishing and refreshing accept a selection:

```json
{
  "skills": [],
  "knowledge_files": [],
  "connectors": []
}
```

Use IDs from share options for skills, knowledge names for `knowledge_files`, and server IDs for `connectors`. Instructions and portable settings are included even with empty selections. Selected skill folders and knowledge contents share limits of 20 MiB and 512 regular files. Symbolic links are rejected. Custom connection URLs with query parameters are excluded from share options.

Review all selected contents and connection URLs before publishing. Stored authentication, conversations, routines, and project files are not bundled. See [Sharing and copies](/developers/guides/sharing) for the recipient experience.

## Preview and import

| Method and path | Behavior |
| --- | --- |
| `GET /v1/agent-templates` | Fluso starting-point snapshots |
| `GET /v1/shared/agents/{share_id}` | Public setup, resource manifest, required filenames, and `published_at` |
| `POST /v1/shared/agents/{share_id}/import` | Authenticated import into the recipient's workspace |

```json
{
  "name": "My release reviewer",
  "project_id": "Home",
  "published_at": "<exact value from the preview>"
}
```

Generate and save a new `Idempotency-Key` for each import. Reuse it and the unchanged body to recover an uncertain import without creating another copy. A changed snapshot returns a conflict rather than silently importing something different from the preview.

The recipient gets independent setup and selected resource copies. Imported custom skills receive distinct names. App credentials are never inherited. Read the imported Agent's `setup_requirements`, then complete missing connections and consent in its manager conversation.

A revoked link becomes unavailable. Unsupported older snapshots may require republication by their owner. Revocation does not delete copies already imported.
