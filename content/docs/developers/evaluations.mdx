The current Agents interface does not include the earlier Evaluations screen, saved Check/Simulation tests, or automatic scores. You can test behavior in an Agent conversation and compare the results yourself.

## Define an observable result

For an escalation Agent, use a synthetic case:

> *"This is a test case: checkout is unavailable for every customer. Classify the severity, identify missing context, and draft the internal escalation. Do not send messages or change any external system."*

Before running it, write down what you expect: a P0 classification, named missing details, and a draft that has not been sent.

For a conversation test, add one follow-up at a time. Check whether the Agent retains the facts and adjusts its result when the situation changes.

## Review tools and shared context

<Warning>
  These are normal Agent turns. They can use connected Apps, write project files, and affect memory. Calling a request a test does not disable tools. Review capabilities and approval settings first; use a separate project and synthetic data when isolation matters.
</Warning>

A duplicate Agent gives you a separate main conversation, but can still use the same project and connections. Select a suitable project and use **Ask me first** with Ask rules for external writes you need to review.

## Repeat after an edit

1. Keep the test prompt and expected result in a file you control.
2. Record the Agent's instructions and result before editing.
3. Save the change, then repeat the case. The main conversation uses the new configuration on its next turn.
4. For an independent conversation, duplicate the updated Agent and review its project and capabilities.
5. Compare correctness, missing information, and approval behavior. Restore the earlier instructions manually if needed.

See [Configuration and sharing](/developers/versions) for copies and [Approvals](/features/approvals) for tool rules.
