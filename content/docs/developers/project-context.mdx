Use **Knowledge files** for stable references. Use project files for working data and deliverables. Keep discussing the work in the main conversation.

## Choose the project before starting

The project setting places the main conversation when it is first created. **Home** is the default. Changing the setting later does not move an existing conversation or its files. Delegated sessions keep their parent's project.

Choose a dedicated project to organize a continuing job's files and memory. A project scopes context. It is not an access-control boundary between Agents in your account. Tools still work in your shared workspace.

## Add reference files

Attach knowledge through the Agent editor, or ask the Manager to attach a file already in your workspace. An Agent can list up to 25 knowledge files, each up to 20 MiB, within your storage allowance.

Knowledge is a **copy**. Editing the original project file does not update the attached copy. Attach and save a replacement when the reference changes. Removing a knowledge entry from the current setup does not remove the older copy from an existing delegated session's setup.

Use project files for a live tracker or an output that must evolve. Use knowledge for a reference edition, such as an agreed review rubric.

<Accordion title="Where each kind of information belongs">
  | Information | Where it belongs | How it is used |
  | --- | --- | --- |
  | Standing rules for the Agent | **Purpose and instructions** | Main conversation on its next turn. Existing delegated sessions retain their setup |
  | A correction for the current task | Your chat message | That conversation or the active turn you steer |
  | Stable reference material | **Knowledge files** | Saved copies listed in the Agent's setup |
  | Working files and deliverables | The project | Shared files that can change as work proceeds |
  | Recent project work | Project working memory | Relevant summaries can be recalled across conversations |
  | Preferences for ordinary chats | Workspace preferences and project context | Not automatically loaded as saved Agent instructions |
</Accordion>

## Know what is shared

Saved Agent conversations use their own instructions instead of automatically applying ordinary-chat preferences, project instructions, or `context.md`. Put a rule in the Agent's saved instructions when it should govern that Agent.

They still receive saved facts from `user_profile.md` and can use project files and project working-memory summaries. Those summaries are background evidence, not new user requests. A fresh session does not automatically receive another conversation's full history. A fork inherits completed context at its creation.

Skill files are also live workspace files. If several Agents use a custom skill, changing that file can affect all of them.

## Verify deliverables

Open the delivered file and check it against your request. A reference in a reply is not proof that the final artifact contains the right data. Ask the Agent to identify unfinished sections, source coverage, and where the result was saved.

Deleting an Agent removes its own knowledge and conversations, not the separate project files. Deleting a project removes its files, conversations, and their routines, but keeps the Agent setup. If the Agent still points to that deleted project, select another **Project** in its setup before opening a new main conversation. This does not restore deleted history.

For file browsing, editing, download, and project export, see [Projects](/features/projects). For sharing an Agent's reference material, see [Sharing and copies](/developers/export-import-and-share-agents).
