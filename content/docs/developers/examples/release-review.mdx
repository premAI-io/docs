A launch decision can depend on several documents: what is changing, what was checked, and what is still unresolved.

An Agent can compare them and keep the open questions together as the evidence changes.

## Give it the decision to help with

Create a reviewer through [New Agent](/developers/agent-builder). Explain what it should check and which decisions remain yours.

> *"Help me decide whether we're ready to launch. Compare the notes, test results, and open issues I share. Tell me what still blocks us and what information is missing. Don't publish anything or contact anyone."*

Then attach the actual material. Explain when you need the decision and what must be true before launch.

## Give different checks room to run

For a larger review, you can ask:

> *"Have one session check what customers will experience and another check the test results. Compare their findings with our launch requirements and bring me one recommendation."*

The Agent can use separate [sessions](/developers/guides/conversations) while it works on the overall review.

In that run, the Agent recommended waiting because checks and approval were still pending. It returned a report with both sessions' findings.

It also misread one progress note as a contradiction. We clarified it in the conversation, and it corrected the saved report.

Read the reasoning, not only the recommendation. An earlier successful check may cover an older version of the work.

## Keep the review useful as things change

Give it the new evidence in the same conversation:

> *"The updated test report is attached. Revise the recommendation, but keep anything we still haven't checked on the open list."*

If the lesson should apply to future reviews, ask [Manager](/developers/improve) to save it.

You can schedule a later check with a [one-time routine](/developers/schedules). That brings the review back at a useful time without creating another conversation.
