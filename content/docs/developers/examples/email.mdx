An email Agent can separate messages that need your decision from messages that need no reply.
Connect [Google Workspace](/integrations/gmail), then select that connection in the Agent's capabilities.

## Start with a review

Create an Agent with this responsibility:

> *"Find mail that needs my attention. Read the latest thread before you recommend a reply. Keep the list short. Do not change my mailbox."*

Give its main conversation a bounded first task:

> *"Review the last 24 hours. Show each unresolved request, its source, and the smallest next step. Draft replies here."*

Check whether a later reply already resolved each request. Check recipients, deadlines, and factual claims in the drafts.
An empty attention list can be the correct result.

## Refine the draft workflow

When the replies are useful, you can ask for drafts inside Gmail:

> *"Save these as replies in their original Gmail threads. Keep the reply-all recipients. Label them 'Review draft'. Do not send them."*

Creating drafts and changing labels are writes. The connection needs **Allowed** access for those actions.
Review [tool approvals](/features/approvals) before you expand access.

For a repeated behavior, open **Edit agent → Manager**:

> *"Save the draft workflow we agreed in the main conversation. Preserve the no-send rule. Never invent a commitment or work status."*

The Manager can inspect the conversation and update the saved setup. Review the resulting instructions.
The main conversation uses them on its next turn.

<Accordion title="A useful correction is specific">
  "Be more accurate" gives little direction. Point to the mistake and the rule it should change.

  > *"The draft promised a delivery date I never approved. Remove that promise. Ask me when a reply needs an unconfirmed date."*

  Ask the Manager to preserve this rule if it should apply to future drafts.
  A one-time instruction to send a reviewed message should not silently become permission to send every future reply.
</Accordion>

## Repeat the review

After one successful review, request a routine in the main conversation:

> *"Every weekday at 9 AM Europe/Zurich, review mail since the last completed check. Avoid duplicate drafts. Report only new decisions and unresolved important requests."*

Check its saved timing in **Routines**. Review the routine's message when you change the workflow.
Saving new Agent instructions does not rewrite an existing routine's message.

## Adapt it for hiring

A Hiring Agent can use the same draft workflow with a narrower responsibility.
Give it the role, candidate, interview duration, permitted dates, and calendars it may check.

> *"Ask this candidate for interview slots next Monday. Prepare a draft. After I send it, check for a reply every 30 minutes until Friday."*

Then define what should happen when a reply arrives:

> *"Check both interviewers' calendars. Draft a confirmation for a free slot. Flag any missing calendar access. Stop checking after the draft or deadline."*

A reply-check routine is a timed check, not an email webhook. A free calendar slot does not create a calendar event.
Confirm who will send the reply and create the invitation.

For other stopping conditions and approval waits, see [Routines](/developers/schedules) and [Inbox](/developers/inbox).
