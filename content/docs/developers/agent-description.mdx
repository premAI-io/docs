An Agent has a **Name** and **Purpose and instructions**. The first line of its instructions provides the short purpose shown in lists. Put the intended result first, then the rules and sources it should use.

| Field | Use it for | Example |
| --- | --- | --- |
| Name | A short label you can find quickly | Customer escalation coordinator |
| Purpose and instructions | Responsibility, expected result, sources, and approval boundaries | Triage customer escalations and prepare a response plan. Classify complete outages as P0. Cite the runbook. Draft external messages for review. |

There are no separate Description or Goal fields in the current editor or create/update API. Integrations should send `instructions`; see [Agents and versions](/developers/api-ref/agents-and-versions).

## When changes apply

Saving an edit changes the configuration used by the main Agent conversation on its next turn. Work already running keeps its accepted configuration. Delegated sessions keep the configuration they received when created.

Conversation history is preserved, so an edited Agent can still see earlier discussion. For a separate test conversation, duplicate the Agent and review its project and capabilities before testing.

Changing the configured project does not move files or existing conversations. See [Project context](/developers/project-context).
