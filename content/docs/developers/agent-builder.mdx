</Note>

Open **Agents → New Agent**. Describe the job to the Agent manager:

> *"Create a customer escalation coordinator. Gather the customer, impact, urgency, and open questions. Read the connected support sources, classify the case as P0 or P1, and prepare the next steps. Ask for approval before sending anything."*

The manager can create and modify saved Agents during the conversation. Review what it creates before using it for live work.

## Describe the job

Name the input and expected result, the sources the Agent may use, and the boundaries it must respect. Keep credentials out of the instructions; connect Apps through **Plugins → MCP**.

For example, refine the Agent with:

> *"Use P0 for a complete outage and P1 for degraded service with a workaround. Prepare customer replies as drafts for review."*

## Use the form

Choose **Fill in a form instead** when creating an Agent, or open **Edit** from an existing Agent's details.

- **Name** is the label shown in the workspace.
- **Purpose and instructions** describe the result, sources, and standing rules.
- Choose the project, response mode, skills, and Apps the Agent can use.
- Add knowledge files for stable reference material.
- Select **Create Agent** or **Save changes**.

The form accepts up to 25 knowledge files, with a 20 MiB limit per file. Review the selected capabilities and [approval settings](/features/approvals) before allowing external changes.

## Refine an existing Agent

Choose **Modify** in the Agent menu to return to the manager. Use **Edit** to change the fields directly.

The main conversation uses the updated configuration on its next turn. A running turn finishes with its accepted configuration, and existing delegated sessions keep theirs. See [Threads and contexts](/developers/threads-and-contexts).
