A routine saves a message to send to an existing Agent conversation at a future time. It can run once or repeat. You do not need to leave the app open.

The routine reuses its target conversation and history. It does not create another Agent or start a blank chat each time.

The current Agent UI supports timed routines. The older Agent webhook editor is no longer available.

## Create a routine

Ask in the Agent's main conversation:

> *"Every weekday at 9:00 AM Europe/Zurich, review the release tracker for new blockers. Return a short update with sources and owners. If nothing changed, say so. Do not send messages to anyone."*

You can also open **Routines** in the Agents sidebar, use the chat's routine control, or select **Routines → Manage** on the setup page. Choose a starting idea or write your own message, select the Agent, set the timing and timezone, and save.

The editor supports one-time, daily, weekday, weekly, and interval presets. Existing custom timing is preserved unless you change its frequency. Timing labels are shown in readable language.

Include the source, expected result, and what to do when there is nothing to report.
For a temporary watch, specify an end date or a result that should stop the checks. For external communications, ask for drafts to review and configure [approvals](/features/approvals).

<Note>
  A routine requested in **Manager** runs a setup review by the Manager. Request the Agent's actual work in its main conversation, or create that routine through the routine editor. Saving instructions alone does not schedule work.
</Note>

## Choose the right repeat pattern

| Job | Useful timing | Completion rule |
| --- | --- | --- |
| Review new email | Recurring review | Report only actionable changes. Avoid duplicate drafts. |
| Finish a large import | One-time continuation | Resume from saved progress. Stop when the remaining work finishes. |
| Check for an interview reply | Recurring check with a deadline | Stop after the requested result or deadline. |
| Prepare a meeting brief | One-time run before the meeting | Check that the meeting still exists at that time. |

Stopping conditions are instructions for the Agent, not automatic expiry settings. Check that it pauses or removes the routine when the condition is met. Creating a routine does not subscribe to live app events.

For a concrete sequence, see [Email and hiring](/developers/examples/email) or [Document filing](/developers/examples/document-filing).

## What happens when it is due

The message enters its target conversation as a separate follow-up. If that conversation is busy, it waits. If an earlier occurrence of the same routine is still queued, running, or awaiting approval, the scheduler waits rather than stacking duplicate work.

In chat, the routine appears as a compact row on the right with a violet clock and scheduled time. Expand it for the instructions, routine ID, and any attachments. The Agent receives the full message even while the row is collapsed.

See the [release review walkthrough](/developers/examples/release-review#return-when-new-evidence-is-ready) for an actual scheduled result.

The main conversation uses the setup selected for the new turn. A routine in an existing delegated session uses that session's earlier setup. Results remain in the target conversation. Top-level routine results can also appear in [Inbox](/developers/inbox).

## Pause, edit, or remove it

Use the routine's pause control to stop future occurrences, edit its instructions or timing, or delete it. Changing Agent instructions does not rewrite a routine's saved message. Review that message after a major workflow change.

Changes do not retract work already admitted into the conversation. Stop that run or cancel its queued message separately if needed.

One-time checks stop scheduling after their message is accepted. **Last run dispatched · outcome unavailable** does not mean the work completed successfully: inspect the result or run status.

Deleting a target session removes its routines. Deleting an Agent removes all of its routines. Archiving a session is not a substitute for pausing its routines.

## More routine controls

<Accordion title="Schedule work in a delegated session">
  Open the session and use its routine control. The sidebar routine editor targets main conversations.
</Accordion>

<Accordion title="Apply the same routine to several Agents">
  The Routines page can apply one instruction and timing to selected Agents. Each gets an independent schedule in its own main conversation.

  **Select all** covers the Agents currently offered by the picker. It does not include Agents created later. Agents already using those instructions at another timing need an explicit selection to add another timing.

  Matching instructions, timing, and timezone are grouped for display. Editing one assignment can split it from its group. Removing one Agent's assignment does not remove the others.

  Saving across several Agents can partly succeed. Successful assignments stay saved. The editor lists the failures. Retry the remaining assignments there instead of creating the whole group again.
</Accordion>

## When a routine does not finish

| What you see | What to do |
| --- | --- |
| Queued | Check the target conversation for ongoing work or a paused queue |
| Waiting for approval | Review the requested action. A routine cannot approve itself |
| Delivery failed or paused with a reason | Fix the connection, unavailable target, or other reported problem, then resume or recreate the routine as appropriate |
| A run failed after starting | Inspect the conversation and partial outputs before continuing |
| Usage allowance reached | Wait for the allowance to reset. Scheduling is deferred rather than treated as a successful run |

<Accordion title="Retries, delays, and clock changes">
  Temporary delivery problems are retried with delays. Repeated delivery failures can pause the routine. Recurring runs do not replay every missed clock tick after a delay.

  Choose a future local time for a one-time check. The editor rejects times that do not exist during a daylight-saving clock change. Review the timezone and next-run time before saving.
</Accordion>

For integrations, these records are called [Schedules in the API](/developers/api-ref/schedules).
